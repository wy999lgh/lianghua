## 一、系统架构总览

```
┌─────────────────────────────────────────────────────────────────┐
│                        前端菜单层                              │
├──────┬──────┬──────┬──────┬──────┬──────┬──────────────────────┤
│网格回测│策略管理│通用回测│ K线图 │数据管理│因子管理│  回测历史  │
└──────┴──────┴──────┴──────┴──────┴──────┴──────────────────────┘
                            │
                            ▼
┌─────────────────────────────────────────────────────────────────┐
│                        API路由层                               │
├─────────────┬─────────────┬─────────────┬──────────────────────┤
│  strategies │   backtest  │   factors   │        data          │
│    .py      │    .py      │    .py      │        .py           │
└─────────────┴─────────────┴─────────────┴──────────────────────┘
                            │
                            ▼
┌─────────────────────────────────────────────────────────────────┐
│                        core核心层                              │
├──────┬──────┬──────┬──────┬────────────────────────────────────┤
│backtest│strategy│ data │analysis│          evaluation         │
└──────┴──────┴──────┴──────┴────────────────────────────────────┘
```

### 架构说明

系统采用**三层架构**设计：

1. **前端菜单层**：提供用户交互界面，包含7个核心功能菜单
2. **API路由层**：处理HTTP请求，作为前后端交互桥梁
3. **core核心层**：实现业务逻辑，包含回测引擎、策略管理、数据处理等核心模块

## 三、core模块详细分析

### 3.1 core/backtest/ - 回测引擎模块

**功能定位**：执行策略回测的核心引擎

| 文件 | 功能说明 | 核心类/函数 |
|------|----------|-------------|
| `backtester.py` | 回测引擎核心组件 | `Backtester`类 - 执行回测主循环 |
| `metrics.py` | 绩效指标计算模块 | `calculate_metrics()` - Sharpe、最大回撤等 |
| `strategy_adapter.py` | 策略适配器 | 统一不同策略的接口调用 |
| `ma_regime_cross_strategy.py` | 均线策略实现 | 牛熊切换策略具体逻辑 |

**回测执行流程**：
```
策略选择 → 数据加载 → 信号生成 → 订单执行 → 持仓管理 → 绩效计算 → 结果输出
```

### 3.2 core/strategy/ - 策略管理模块

**功能定位**：策略定义、注册和管理

| 文件 | 功能说明 | 核心策略/类 |
|------|----------|-------------|
| `base_strategy.py` | 策略基类 | `BaseStrategy` - 定义策略接口规范 |
| `grid_strategy.py` | 网格交易策略 | 区间交易、自动买卖逻辑 |
| `standard_strategy.py` | 标准策略模板 | 通用策略框架 |
| `strategy_manager.py` | 策略管理器 | 策略注册、加载、实例化 |
| `strategies/grid_strategy.py` | 网格策略具体实现 | 价格区间划分与交易规则 |
| `strategies/ma_regime_strategy.py` | 均线牛熊策略 | MA200判断牛熊市切换 |
| `strategies/trend_resonance_regime_strategy.py` | 趋势共振策略 | 多周期共振信号 |

**策略注册机制**：
```python
# strategy_manager.py 自动发现并注册策略
strategies = {
    "grid": GridStrategy,
    "ma_regime": MARegimeStrategy,
    "trend_resonance": TrendResonanceStrategy
}
```

### 3.3 core/data/ - 数据管理模块

**功能定位**：数据获取、清洗、存储和管理

| 文件 | 功能说明 | 核心能力 |
|------|----------|----------|
| `database.py` | 数据库接口 | PostgreSQL连接、数据读写操作 |
| `data_fetcher.py` | 数据获取 | 从外部数据源获取行情数据 |
| `data_cleaner.py` | 数据清洗 | 缺失值处理、异常值过滤 |
| `data_pipeline.py` | 数据管道 | 数据流转处理流程 |
| `models.py` | 数据模型 | 数据结构定义 |

**核心数据库表**：
- `stock_daily_{symbol}` - 股票日线数据表
- `strategy_configs` - 策略配置表
- `backtest_results` - 回测结果表
- `factor_configs` - 因子配置表

### 3.4 core/analysis/ - 因子分析模块

**功能定位**：因子计算与预处理

| 文件 | 功能说明 | 核心处理能力 |
|------|----------|-------------|
| `factor_library.py` | 因子计算库 | MA、EMA、MACD、RSI等技术指标 |
| `factor_processor.py` | 因子预处理 | 缺失值→去极值→标准化→中性化 |

**因子处理流水线**：
```
原始因子 → 缺失值处理(ffill/mean/median) 
         → 去极值(MAD/IQR/percentile) 
         → 标准化(Z-score/MinMax/rank) 
         → 中性化(市场中性)
```

### 3.5 core/evaluation/ - 评估报告模块

**功能定位**：回测结果评估与报告生成

| 文件 | 功能说明 | 输出形式 |
|------|----------|----------|
| `report_generator.py` | 报告生成器 | 绩效指标汇总统计 |
| `report_exporter.py` | 报告导出 | CSV/Markdown格式导出 |
| `markdown_report.py` | Markdown报告 | 格式化报告输出 |
| `bias_checker.py` | 偏差检查 | 回测结果验证与偏差检测 |

## 五、菜单功能关系总结

### 5.1 策略管理 vs 通用回测对比

| 对比维度 | 策略管理 | 通用回测 |
|----------|----------|----------|
| **核心定位** | 策略定义与持久化配置 | 策略执行与临时测试 |
| **数据持久化** | ✅ 保存到数据库 | ❌ 临时执行，不保存 |
| **使用场景** | 长期策略配置管理 | 快速测试不同参数组合 |
| **参数修改位置** | ⭐ 推荐位置 | 仅临时测试 |
| **适用场景** | 正式策略部署 | 策略研究与验证 |

### 5.2 系统数据流关系

```
策略管理(定义策略) → 通用回测(执行回测) → 回测历史(存储结果)
     ↓                                              ↑
     └───────────────── 策略配置引用 ─────────────────┘

数据管理 → 因子管理 → 策略管理 → 通用回测
   │           │           │
   └───────────┴───────────┘
            ↓
         K线图(数据展示)
```

### 5.3 策略参数修改位置建议

**推荐位置：策略管理菜单**

**操作路径：**
```
策略管理 → 选择策略 → 点击"详情"按钮 → 点击"修改参数"按钮 → 修改参数 → 保存配置
```

**推荐理由：**
1. 参数保存在数据库，下次使用自动加载
2. 便于策略版本管理和配置追溯
3. 与策略定义逻辑保持统一
4. 支持多人协作共享策略配置
